# Store contract

One Store owns the SQLite connection and advisory process lock for a private local state directory. Linux is the supported server platform. SQLite uses WAL, FULL synchronous commits, foreign keys and a bounded busy timeout. Database queries and staging batches are bounded. No transaction spans tape I/O. UUIDs are generated for jobs and validated for locally registered volumes, timestamps use UTC RFC3339Nano, and sizes use signed 64-bit values.

Migrations 001 and 002 have persisted SHA-256 checksums. Migration 002 adds durable cancellation, media recheck and local enrollment. Future versions are refused and changes to an applied migration are refused. Migration DDL and its history row commit in one transaction, which rolls back on failure. Before upgrading an existing schema, Open automatically calls the tested online Backup method into a fresh pre-migration snapshot. Preserve the old executable/configuration alongside that snapshot. Downgrades to an unsupported schema must use that prior snapshot in a fresh state directory. Never copy an active catalog database without its WAL.

CreateVolume reserves an uninitialized blank candidate or records legacy/unclassified media. Only PublishInitializedVolume may make a newly initialized volume MANAGED with its header digest after matching exact readback to durable expected bytes. The engine still must establish local authorization, lease, fresh identity, blank classification and profile before the write intent. Store state is never a write permit.

The backup flow claims a job, records an intent, marks write-open possibility before opening the writer, records expected data and commit values, enters VERIFYING, stages the actual scanned members under the job ID, then calls PublishArchive. Publication checks the expected volume, indices, digests and byte count, stores evidence and catalog rows and marks success within one SQLite transaction. The engine supplies complete independently scanned evidence and observes subprocess/write/close errors before invoking this boundary.

A restarted active job becomes FAILED when effects are known safe, or RECOVERY_REQUIRED for a possible write or uncertain restore publication. The media is quarantined in the same transaction. Queued and waiting jobs retain their states. No operation in this package executes tape I/O or retries writes. Sealing or quarantining is supported, while clearing protection needs a future explicit investigation workflow.

Backup uses the driver's SQLite online backup API and validates the completed snapshot with quick_check, fsync and restrictive permissions. The destination must be fresh inside a private directory. It can be opened as catalog.db in another private directory for recovery. Export paths belong to the host configuration and must never come directly from an HTTP request.

Migration 014 adds durable managed-media verification assessments. Each attempt binds the fresh UUID and exact header digest under the lease. Passing pairs remain staged until resource close; successful current integrity and readback evidence commit with the terminal job outcome. Confirmed bad pairs become `FAILED`; unread pairs become `UNKNOWN`, retaining earlier timestamps and baseline digests/provenance. Previously known `FAILED` rows remain failed until directly reverified. Cancellation alone does not claim corruption or quarantine media. Descriptor-close, identity-change and process-crash uncertainty withdraw staged success; startup never promotes an unclosed checkpoint. Readback cannot enroll or unseal media and cannot establish extraction-graph eligibility.

The same migration repairs pre-014 stale green state from historical `VERIFY` jobs that reached `readback` and ended `RECOVERY_REQUIRED`. It withdraws only archive rows whose latest recorded evidence predates that failure, preserving the failed attempt's explicitly recorded valid prefix and later readback/backup/import evidence. UTC instants are normalized before comparison. Wrong-media/preflight failures do not identify a scope and cannot degrade expected catalog media. Historical timestamps and digests remain intact; affected media is quarantined unless already sealed. The v13 upgrade regression exercises fractional-second ordering and these exclusions.
