# Administrator authentication

Bootstrap with the local interactive command `tapepilot -config FILE admin bootstrap`. Reset with `tapepilot -config FILE admin reset`. The backend must release its exclusive state ownership before an offline command opens the installation. Password entry requires a terminal and disables echo. Arguments, environment variables and configuration do not carry the password. Reset changes the credential version and revokes every session atomically. Tests may use Bootstrap and Reset directly to prepare synthetic local fixtures.

Passwords use Argon2id with a random 16-byte salt, 64 MiB memory, three passes, two lanes and a 32-byte result. Parameters are stored in the PHC hash string. The password policy accepts 12 through 1024 valid UTF-8 bytes. Only the supported bounded profile is decoded, preventing a corrupt hash from requesting arbitrary memory or work. A three-iteration local benchmark measured 50.588111 milliseconds per derivation and 67,118,210 allocated bytes on the Intel i5-12500T fixture. Login permits at most two simultaneous derivations. Reproduce with `go test ./internal/auth -run '^$' -bench BenchmarkPasswordHash -benchtime=3x -benchmem`.

The browser first requests GET /api/v1/auth/session, receiving authenticated and csrf_token fields plus an anonymous HttpOnly cookie when required. POST login sends one password JSON field, the exact configured Origin and X-CSRF-Token. A successful login replaces the anonymous session with a fresh opaque random cookie. CSRF is a domain-separated SHA-256 derivation of that 256-bit cookie secret. Its value is unavailable to a cross-origin page under the browser same-origin policy. Login requires CSRF protection as well as every administrative mutation. Logout revokes the session and returns a fresh anonymous session.

The database stores session token hashes. Authenticated sessions expire after 12 hours absolutely or 30 minutes of inactivity. Anonymous sessions expire after 15 minutes. Password reset increments the administrator version, so a credential check racing reset cannot create a session with the old version. Login success audit and rotation share a transaction. Cookies use Path=/, HttpOnly and SameSite=Strict. HTTPS adds Secure and the browser-enforced __Host- cookie prefix. HTTP origins require an explicit loopback address or localhost. Exact configured Host and Origin checks reject cross-site requests. Forwarded headers supply no authentication trust.

Login rate controls bound each remote address and aggregate work. Forwarded client addresses are ignored. Rate maps cap at 256 entries, anonymous sessions at 128 and authenticated sessions at 16. Expired rows are pruned before issuing another session. Request IDs are generated by the server. Authentication failures return stable sanitized codes without credentials or subprocess output. API responses disable caching, and auth routes grant no CORS access.

Auth.Wrap protects operational routes while allowing minimal public health and the guarded authentication routes. RequestID and WriteError provide the shared error envelope. Long-lived SSE handlers call ValidSession periodically. That method checks revocation and expiry without extending idle expiry. Local write enrollment and initialization authorization continue to use their independent operator controls.

The pinned Go crypto, terminal and system packages carry BSD-style Go licenses. The authentication scan after upgrading golang.org/x/crypto to v0.59.0 reported no vulnerabilities. The selected dependency graph includes x/term v0.48.0 and x/sys v0.50.0. No SSH or OpenPGP runtime features are used.
